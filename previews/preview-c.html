01 MTest Labs: a test design tool the testers run themselvesclient build · multi-agent · knowledge assistant · review gate 1 to 3 hrsfrom Dec 2025

Client build · Software testing firm · from Dec 2025

An internal tool with its own interface that drafts tailored test scenarios and cases

Test design used to take a full 8 hour day, or 2 to 3 days on larger projects.

What
A tool that gathers full project context from the firm's documentation and a structured question flow, then generates tailored test scenarios and cases. I also added a conversational assistant so the team can query the firm's knowledge.
Why
Test design was manual and slow: a full 8 hour day, or 2 to 3 days on larger projects.
How
A staged, multi-agent orchestration grounded in the firm's own test-case library and historical issue logs. Refined through build, test and improve cycles with the testers.
Who uses it
The testers. I trained the team to run it themselves and left documentation.
Result
Test design cut to 1 to 3 hours of supervised draft-and-review.
Before
  1. Tester reads the project documentation
  2. Writes scenarios and cases by hand
  3. A full 8 hour day, or 2 to 3 days on larger projects
After
  1. Documentation plus a structured question flow
  2. Staged agents draft from the firm's library and issue logs
  3. Person reviews: a tester approves every output before anything reaches a client
  4. 1 to 3 hours of supervised draft-and-review

Client build · Interior design business · from Dec 2025

Automated workflows across operations, marketing and finance, plus a Power BI management view

Built for a small, varied business run by a non-technical owner.

What
Dozens of workflows across operations, marketing (including lead follow-up) and finance, connecting steps that had been handled separately. A Power BI dashboard replaced a rekeyed monthly management pack.
Why
Operations, marketing and finance steps were handled separately and manually, from first enquiry through to delivery.
How

Result
Dozens of workflows automated. The monthly pack is a Power BI dashboard instead of a rekeying job.

04Ideas for Shanly

Three small starting points, one per business.

I do not know your internal systems. Each idea uses Microsoft 365 tools you already have, and each starting point is an assumption to check with the team.

Illustrative: how I would approach this in my first months, to be agreed with the Deputy Chairman

Sorbon Estates: maintenance requests

Sorbon looks after marinas, offices, shops, industrial units and parking. One request route would let a tenant report an issue once and see where it is.

Assumed starting point, to check with the team
  1. Requests arrive by email or phone
  2. Tracked by hand
  3. Status chased one by one
Approach
  1. Microsoft Form to a SharePoint list
  2. Power Automate routes by property and type
  3. Person reviews: the property manager approves the job
  4. Teams notification, Power BI status view
Mock-up · Sample data · Sorbon maintenance request6 steps
  1. Tenant submits a Microsoft Form (sample: shore power point not working at a marina berth).
  2. The form adds a row to a SharePoint list with a reference.
  3. Power Automate routes it to the right property manager.
  4. Person reviews: the property manager approves the job and contractor.
  5. Teams notifies the contractor, and the tenant gets an update.
  6. Power BI shows open, approved and closed requests.

Illustrative: how I would approach this in my first months, to be agreed with the Deputy Chairman

Build, buy or simplify: a one-page check for existing software

  1. What job does this software do, and who does that job today?
  2. Can the step be removed or simplified before any tool is chosen?
  3. Can Microsoft 365, Power Platform or Copilot already do it?
  4. Can the IT Manager and external IT partners support it?
  5. Can we trial it small with the people who will use it?
  6. Who owns it, and where is it documented?
